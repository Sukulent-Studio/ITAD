# Витрина Seoul Bike Sharing

## 1. Модель

**Выбранный вопрос:** Как различается спрос на аренду велосипедов по сезонам и часам суток?

**Гранулярность:** одна строка таблицы `rent` представляет один час работы системы
велопроката Сеула в определённую календарную дату из снимка `staging`. Источник уже
агрегирован по часу: строка не является отдельной поездкой. Все строки
`staging` сохраняются, без дедупликации и фильтрации.

**Ключ:** составной бизнес-ключ `(Date, Hour)` идентифицирует час наблюдения системы
внутри этого периода. В ЛР № 3 проверены его заполненность и уникальность: 0 пропусков,
0 повторов и 0 полных дубликатов на 8 760 строках. Технический идентификатор не создаётся.

**Срезы:** `Seasons` (Winter, Spring, Summer, Autumn), `Hour` (0–23) и их сочетание.

| Мера | Единица и использование | Правила агрегации |
| --- | --- | --- |
| `Rented Bike Count` | Число арендованных велосипедов за час; основная мера спроса для среднего и сезонной доли | Суммировать можно по непересекающимся часам. Среднее пересчитывать по строкам; средние групп не складывать, а для объединения учитывать число наблюдений. |
| `count(*)` | Число часовых наблюдений, не число аренд; контроль покрытия и знаменатель среднего | Суммировать по непересекающимся группам часов. Не подменять этой величиной число аренд. |

Доля аренд сезона — сумма `Rented Bike Count` за сезон, делённая на сумму аренд
за весь выбранный период. Сезонные суммы складываются между непересекающимися сезонами;
доли и средние значения не складываются.

`Functioning Day = false` означает недоступность сервиса. Нулевые аренды в такие часы
не следует трактовать как отсутствие спроса: при расчёте среднего их нужно исключать
из знаменателя либо показывать отдельно. Строки при этом остаются в витрине и учитываются
в покрытии. По отчёту ЛР № 3 в снимке 295 нерабочих часов, нарушений согласованности
и выставленных quality-флагов нет.

Период наблюдения — `2017-12-01`–`2018-11-30`, один полный год. `2026-10-15` в пути —
логическая дата загрузки исходного снимка, не время наблюдения. Выбранная модель
поддерживает сравнение только для этого периода; сезонные различия не обобщаются
автоматически на другие годы.

Используется одна широкая почасовая таблица: все необходимые для вопроса временные
срезы, мера аренд и флаг рабочего времени относятся к одной строке и не требуют
отдельных таблиц измерений.

## 2. Сопоставление полей

Путь результата: `s3://mart/seoul_bike/source_ingested_on=2026-10-15/rent.parquet`.
Логическая дата взята из пути входного `staging`. Техническая дата загрузки хранится
в пути, а не используется как дата наблюдения.

Названия полей в `rent` будут приведены в `snake_case` для удобства использования.

| Поле в `rent`| Поле в источнике (`staging`) | Преобразование | Смысл, единица или ограничение |
| --- | --- | --- | --- |
| `date` | `Date` | Перенос без изменения (`DATE`) | Календарная дата часового наблюдения; часть ключа. Период 2017-12-01–2018-11-30. |
| `hour` | `Hour` | Перенос без изменения (`BIGINT`) | Час суток 0–23; срез и часть ключа. |
| `seasons` | `Seasons` | Перенос без изменения (`VARCHAR`) | Сезонное измерение: Winter, Spring, Summer, Autumn. |
| `rented_bike_count` | `Rented Bike Count` | Перенос без изменения (`BIGINT`) | Число аренд за час. Отрицательные значения исключены на этапе контроля качества ЛР № 3. |
| `functioning_day` | `Functioning Day` | Перенос без изменения (`BOOLEAN`) | Признак доступности сервиса; `false` требует отдельной обработки в среднем спроса. |
| `functioning_day_violation` | `quality_functioning_day_consistency_violated` | Перенос без изменения (`BOOLEAN`) | Флаг проверки согласованности рабочего дня и аренд.  |

## 3. Проверки и ограничения

Проверки ключа и исходных полей выполнены в ЛР № 3: [отчёт о качестве](data_quality_report.md)
и [ноутбук профилирования](../notebooks/profile_quality.ipynb). В этом снимке подтверждены
8 760 строк, отсутствие пропусков и повторов по `(Date, Hour)`, корректные сезоны и часы,
неотрицательное число аренд и согласованность признака `Functioning Day`.

При сборке витрины следует проверить сохранение числа строк и ключа, схему, диапазон
`Hour`, отсутствие пропусков в мере и точный перенос quality-флага. Среднее спроса
требует отдельного решения по 295 нерабочим часам. Ограничения периода, интерпретации
нулей и неудовлетворённого спроса описаны в [отчёте ЛР № 3](data_quality_report.md).
