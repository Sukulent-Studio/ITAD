# Метрики Seoul Bike Sharing Demand

## Вопрос и вход

В ЛР № 5 рассматривается вопрос: как различается спрос на аренду велосипедов по сезонам и часам суток?

Вход - витрина ЛР № 4:
s3://mart/seoul_bike/source_ingested_on=2026-11-12/rent.parquet

Период по Date: [2017-12-01, 2018-12-01). Одна строка - один час работы системы велопроката в конкретную дату. Бизнес-ключ (date, hour) уникален, технического суррогатного ключа нет.

## Метрики и окно

Правила применяются к общему итогу и к каждой группе отдельно.

| Метрика | Расчёт и участвующие значения | Единица |
|---|---|---|
| Число записей | `count(*)` - все часовые записи периода, включая нерабочие часы | Записи |
| Суммарное число аренд | `sum(rented_bike_count)` - все часовые записи периода; нули нерабочих часов не искажают сумму | Шт. |
| Среднее число аренд в час | `avg(rented_bike_count) FILTER (WHERE functioning_day)` - только рабочие часы, нули нерабочих исключены | Шт./час |

295 нерабочих часов не входят в расчёт среднего числа аренд, но соответствующие записи остаются в общем количестве и учитываются в сумме. В расчёт среднего входят 8465 значений. Нули в нерабочие часы означают недоступность сервиса, а не отсутствие спроса, поэтому их исключение из знаменателя - обязательное решение о качестве из ЛР № 3.

Рядом со средним выводится `working_count` - число участвующих рабочих часов. В группировках сохраняется также `total_rentals` - их сумма. Для проверки общего среднего используется `sum(total_rentals) / sum(working_count)`, а не простое среднее групповых средних.

Окно добавляет `percent_of_rentals` - долю аренд часа в общем объёме аренд за период, в процентах: `100.0 * total_rentals / nullif(sum(total_rentals) OVER (), 0)`. Оно применяется после группировки: числитель относится к одному часу, знаменатель - ко всем часам. `NULLIF` защищает от нулевого знаменателя.

## Результаты

Расчёт находится в [calculate_metrics.ipynb](../notebooks/calculate_metrics.ipynb). Рабочая входная выборка и результаты материализованы во временных таблицах DuckDB в памяти. Последующие запросы используют эти данные без повторного чтения S3. Помимо общего итога `overall_raw`, подготовлены три результата:

| Временная таблица DuckDB / переменная Python | Смысл одной строки и содержимое | Использование в ЛР № 7 |
|---|---|---|
| hourly_metrics / hourly_raw, 24 строки | Час суток - три метрики, размеры групп, знаменатель для среднего и доля аренд | Сравнение метрик по часам |
| segment_metrics / segment_rows, 96 строк | Сезон и час - те же метрики, размеры групп и знаменатель для среднего | Уточнение общей картины по сезонам |
| distribution_values / rentals, 8 465 строк | Число аренд за один час - записи только для рабочих часов | Распределение числа аренд |

Все часы и все имеющиеся сочетания сезона и часа рассчитаны за год. Отсутствующее сочетание не подменяется нулём. Распределение строится из отдельных значений аренд, его нельзя восстановить по средним групп. Ограничение: данные описывают один год, поэтому сезонные сравнения не гарантируют повторения в другие годы.

Все четыре проверки пройдены. Они подтверждают согласованность расчётов и то, что среднее значение рассчитано с правильными весами (`working_count`), а не как простое среднее групповых средних.

## Вывод

Общее среднее число аренд в рабочий час составляет 729.16. В час 4 зарегистрировано в среднем 137.49 аренд, в час 18 - 1554.02. Размер сравниваемых групп составляет около 350 наблюдений на каждый час, поэтому выборочные средние достаточно устойчивы. Различие видно по числам, но группы различаются по сезонному составу. Один год наблюдений в Сеуле не позволяет объяснить причины этих различий без привлечения дополнительных данных. Наблюдаемое различие само по себе не доказывает причинно-следственную связь.
